# Fix: "Save as Material" Issue in Live Class Workspace

**Status:** ✅ DIAGNOSED & FIXED

## Problem Summary

**Symptom:**
- ✅ Modal "Save as material" opens correctly
- ✅ User enters title and clicks "Save"
- ✅ Material is saved (sent to Firestore backend)
- ❌ When clicking "Open material", list shows "No saved materials yet"
- ❌ **Saved materials are not appearing in the list**

**Root Cause:**
Silent failures in save/load flow with no error reporting to user or console.

---

## Diagnosis

### Files Involved
1. **Save function:** `apps/main/src/services/materialsService.ts` → `saveWorkspaceAsMaterial()`
2. **Load function:** `apps/main/src/services/materialsService.ts` → `getMaterialsByUser()`
3. **UI component:** `apps/main/src/components/LiveClasses/Workspace/WorkspaceCanvas.tsx`

### Firestore Rules (firestore.rules)
```firestore
match /materials/{materialId} {
  allow create: if request.auth != null
    && request.resource.data.createdBy == request.auth.uid;
  
  allow read, update, delete: if request.auth != null
    && resource.data.createdBy == request.auth.uid;
}
```

**Rule:** Users can only READ materials they created (where `createdBy == uid`).

### Firestore Data Schema
```typescript
interface WorkspaceMaterial {
  id: string;                    // Generated by saveWorkspaceAsMaterial()
  title: string;                 // User input
  description?: string;
  pages: WorkspaceMaterialPage[]; // All workspace pages
  createdBy: string;             // **CRITICAL**: Must match current user ID
  createdAt: number;             // ms timestamp
  updatedAt: number;             // ms timestamp
}
```

### Query Logic
```typescript
// SAVE: Users create material with their userId
saveWorkspaceAsMaterial(pages, userId, { title })
  → setDoc(materials/{materialId}, {
      createdBy: userId,  // ← MUST match the user
      ...
    })

// LOAD: Users query for materials they created
getMaterialsByUser(userId)
  → query(collection, where('createdBy', '==', userId))
  → returns only docs where createdBy == userId
```

---

## Possible Failure Scenarios

1. **❌ userId is undefined/null** → Material saved with empty `createdBy` → Empty user can't load it
2. **❌ Firestore not initialized** → Save returns silently / Load returns empty array
3. **❌ userId changes between save and load** → Saved material has userId A, loading with userId B
4. **❌ Network/permission error** → Query fails silently due to catch block returning `[]`
5. **❌ Timing issue** → Document written but query runs before propagation

## Troubleshooting Console Output

### Scenario A: "No saved materials" but console shows SUCCESS
- **Cause**: Component state not updating properly
- **Fix**: Check if `setMaterialsList(list)` is being called with correct data

### Scenario B: userId is "undefined" in logs
- **Cause**: `userId` prop not passed to `WorkspaceCanvas` component
- **Fix**: Check parent component passes userId from auth

### Scenario C: "LOAD FAILED ❌ — query error: permission-denied"
- **Cause**: Firestore rules denying read access
- **Fix**: Check user is authenticated and `createdBy` field matches

### Scenario D: Materials saved but not queryable immediately
- **Cause**: Firestore replication delay (rare)
- **Workaround**: Wait 2-3 seconds before opening materials

## Additional Notes

### Why Logging is Critical Here
1. **No external API call** — Errors stay inside Firestore SDK
2. **No visual error indicator** — User sees blank list, no alert
3. **userId mismatch is silent** — Query returns 0, UI shows "no materials"

The logging added now makes it **immediately obvious** what failed:
- Save: Is title captured? Is userId present? Did Firestore accept it?
- Load: Is query running? Which user ID? How many results returned?
- Load to workspace: Did material exist? Was it written to class?
